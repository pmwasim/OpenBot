# OpenBot v0.3.9 protocol compatibility assessment

Date: 2026-08-27

## Product result

OpenBot can now connect to two local model HTTP shapes without a code change in the application: the existing native protocol remains the default, while `OPENBOT_MODEL_PROTOCOL=chat-completions` uses `/v1/models` and `/v1/chat/completions`. Both paths retain the configured model URL and local-only loopback restriction.

This expands the set of lightweight local runtimes an older laptop can use without adding a hosted dependency, account, GPU requirement, or paid service. The model still determines whether natural-language reasoning is practical on a particular machine.

## Verification evidence

- `npm run check`: 81/81 release-harness checks passed.
- The harness exercised a live loopback fixture for model discovery and structured chat response normalization.
- Native protocol behavior remains the default and existing approval/workspace/audit tests remain green.
- Configuration output exposes the selected protocol without exposing credentials.
- Public product surfaces remain brand-neutral.

## Security and remaining gaps

The alternate protocol does not weaken the local-only endpoint check; remote model endpoints still require explicit opt-in. Request size, timeout, structured response parsing, turn/action limits, approval gates, workspace containment, and audit redaction remain shared controls.

The remote-compatible provider remains intentionally incomplete, and provider credentials are not yet stored in an OS-backed secret store. Packaging, daemon service installation, richer streaming/cancellation, multi-user identity, connectors, and desktop automation remain future work.
