# OpenBot v0.4.30 local connectors assessment

Date: 2026-08-27  
Release: v0.4.30  
Scope: operator-owned read-only HTTP connectors across the shared daemon, API, CLI, dashboard, runtime, policy, agent, and audit surfaces.

## Outcome

The release turns the connector registry into a usable bot capability rather than a dashboard-only configuration surface. An operator can register an HTTP endpoint and explicit absolute paths, inspect it locally or through the shared daemon, and let the agent request a read through `connector.fetch`. Each request is stopped at the existing approval boundary before network access.

## Implemented

- Durable connector definitions with bounded name, description, count, path, response, and timeout limits.
- URL validation rejects credentials, queries, fragments, unsupported protocols, malformed paths, traversal segments, and host changes.
- Exact host policy reuses the loopback default and explicit `OPENBOT_BROWSER_ALLOW_HOSTS` configuration.
- Exact registered paths with safe prefix semantics; only enabled connectors can be used.
- GET-only fetches with disabled redirects, 64 KiB response cap, and 10-second timeout.
- Approval action digests include the connector id, endpoint, enabled state, and path allowlist, invalidating an approval if the definition changes.
- API, dashboard, local CLI, shared-daemon CLI, runtime, and agent context expose the same connector contract.
- Connector response and audit delivery remain redacted and bounded; definitions do not store credentials.

## Deliberate limits

Connectors are not general plugins or process extensions. They cannot execute code, send arbitrary methods, attach credentials, follow redirects, bypass approvals, or leave the configured host/path boundary. Signed extensions, richer tool discovery, OAuth, multi-user authorization, and full MCP compatibility remain future work.

## Release decision

Release when the final exact-commit security scan reports complete coverage with zero validated findings, the public tag points to that audited commit, and the worktree is clean.
