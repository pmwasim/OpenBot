# OpenBot v0.4.2 task activity assessment

Date: 2026-08-27  
Scope: incremental task activity visibility  
Audited implementation commit: 134fb3d092259dab4a6ecb261b9122cc5790768e

## Product result

OpenBot now exposes task activity incrementally through `GET /api/tasks/:id/events?after=<offset>`. Clients receive the task snapshot, events appended after the supplied non-negative offset, and the next offset. The dashboard uses this endpoint to show the latest durable activity and polls only while work is pending, running, or waiting for approval.

This gives the local bot a practical progress surface for the dashboard and lightweight clients without requiring a permanent connection, a second service, or a hosted component. Full-duplex event streaming remains a separate future capability.

## Evidence

- The release harness passed 86/86 checks, including a live task-event read and an exhausted offset read.
- The event feed reuses the existing append-only task history and returns only events bound to the requested task.
- Invalid offsets are rejected, unknown tasks remain 404, and the existing audit endpoint is unchanged.
- No runtime dependency, hosted service, account, telemetry, or paid integration was added.

## Older-laptop assessment

The dashboard performs one small request every 1.5 seconds only while active work exists. Completed or idle dashboards do not keep polling. The feature uses the stock HTTP and browser APIs, does not start another process, and does not keep a permanent connection open.

## Security boundary

The task endpoint remains behind the server's existing loopback/LAN authentication boundary. Event payloads come from the same redacted append-only history used by task audits; the endpoint does not expose arbitrary store records or workspace files. The dashboard renders event summaries with text nodes rather than HTML injection.

## Remaining gaps

- Full-duplex streaming, notifications, cancellation controls, and a general remote client remain future work.
- The local daemon must remain running and the host must remain available for live activity updates.
- Multi-user identity, connectors, desktop automation, and remote workers remain incomplete.
