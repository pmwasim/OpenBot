# OpenBot v0.4.32 automatic resource profile assessment

Release: v0.4.32  
Assessment date: 2026-08-27  
Scope: automatic local hardware-based selection for the existing bounded resource profiles.

## Outcome

Pass for release. OpenBot now accepts `OPENBOT_RESOURCE_PROFILE=auto` and selects the existing `legacy` profile when the local host reports 2 or fewer logical CPUs or less than 8 GiB of memory. Otherwise it selects `standard`. The requested mode and effective profile are visible through `doctor --json` and the read-only dashboard Settings view.

The feature remains zero-cost and local-first: it uses Node's built-in operating-system signals, adds no dependency, does not install software, and does not contact a remote service. Explicit `legacy` and `standard` values remain available for deterministic operator overrides.

## Product assessment

- This closes a concrete old-laptop usability gap: operators no longer need to know which bounded profile to choose before starting a local daemon.
- The selection is transparent rather than silent. Doctor reports both `mode` and `profile`, and Settings reports the same effective values.
- The profile controls bounded turns, actions, context size, and the default isolation expectation. It does not claim that every local model will run quickly on older hardware.
- Natural-language reasoning still requires an installed local model. Core administration and allowlisted diagnostics remain available without one.
- Public repository surfaces remain brand-neutral.

## Technical assessment

- CPU signal: Node `availableParallelism()` unless `OPENBOT_CPU_COUNT` is supplied for deterministic testing or controlled environments.
- Memory signal: Node `totalmem()` unless `OPENBOT_MEMORY_BYTES` is supplied for deterministic testing or controlled environments.
- Legacy threshold: CPU count `<= 2` OR memory `< 8 GiB`.
- Standard boundary: exactly 8 GiB with more than 2 logical CPUs remains standard.
- Explicit `OPENBOT_ISOLATION` continues to take precedence over the profile-derived isolation default.
- The shell worker uses the same profile selection as configuration, so automatic legacy mode is not merely cosmetic.

## Verification evidence

- `npm run check` — PASS, 143/143 release checks.
- Coverage includes auto legacy selection, auto standard selection, low-memory selection, the exact 8 GiB boundary, public configuration redaction, CLI doctor output, and the existing legacy shell safety path.
- No new package or mandatory service was introduced.

## Known limits

Automatic selection is a bounded-work safeguard, not hardware benchmarking or model optimization. It does not inspect model size, thermal throttling, battery state, disk space, or actual response latency. Operators can override it explicitly when their local workload justifies a different bounded profile.
