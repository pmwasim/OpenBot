# OpenBot v0.4.12 dashboard task-control assessment

Date: 2026-08-27  
Scope: dashboard pause, resume, and cancel controls for durable tasks  
Audited implementation commit: f722d961354a4e1d9d4bbe6151c4751259eff380

## Product result

OpenBot operators can now control recoverable work from recent-task dashboard cards. Pending, running, and approval-bound tasks expose Pause; paused tasks remain resumable; all nonterminal controllable states expose Cancel task. Each action uses the existing durable task-state endpoint and refreshes task activity and approvals after completion.

The dashboard does not invent a second task controller or bypass the server's state-transition rules. Invalid or stale actions return a visible error and leave the control available for a retry or a fresh state refresh.

## Evidence

- The fresh release harness passed 94/94 checks after the implementation commit.
- The harness covers the dashboard task-control contract, existing API and CLI task controls, approval boundaries, task recovery, activity cursors, workspace containment, audit redaction, and public-surface brand neutrality.
- `node --check server.mjs`, `node --check public/app.js`, and `git diff --check` passed.
- No runtime dependency, hosted service, account, telemetry, or paid integration was added.

## Older-laptop assessment

Task control is one local HTTP request followed by a bounded state refresh. It does not start a model process, create a second controller, or increase agent turn/action limits.

## Security boundary

The browser sends only the task id and one of the server-allowlisted actions, `pause` or `cancel`. Resume continues to use the existing resume route. The server store remains authoritative for allowed source states and durable status transitions; task ids are URL-encoded before browser requests.

## Remaining gaps

- Native desktop packaging, notifications, full-duplex streaming, multi-user identity, connectors, signed extensions, and remote workers remain incomplete.
