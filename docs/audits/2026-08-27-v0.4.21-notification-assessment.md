# OpenBot v0.4.21 notification assessment

Date: 2026-08-27  
Implementation commit: `2671c199db1b2c6393177bd81b0dfcda25e4ce8e`

## Outcome

OpenBot v0.4.21 adds optional browser notifications for tasks started in the current dashboard session. The operator explicitly enables permission from the dashboard; a notification is emitted when that task completes, fails, or is cancelled. The feature uses the browser's built-in notification API and does not add a daemon, background service, account, dependency, or cost.

## Product assessment

This closes a practical background-use gap for a local bot: the operator can leave a task running and receive a completion signal without keeping the dashboard in the foreground. Notifications are scoped to tasks initiated in the open dashboard session, so loading historical tasks does not create unexpected notifications. Mobile notifications and OS-level daemon notifications remain future work.

## Security and privacy assessment

No task content is sent to a new service. The notification body is limited to the persisted result or error and truncated to a bounded length. Permission is requested only after an explicit user click. Unsupported browsers and denied permission are handled without breaking task execution or event monitoring. The change does not alter provider, approval, policy, workspace, authentication, cancellation, or audit boundaries.

## Remaining gaps

Mobile/OS-level notifications, configurable notification preferences, richer result artifacts, desktop automation, connectors, signed extensions, collaboration, multi-user authentication, remote workers, and full-duplex clients remain future work. These are intentionally not represented as completed by v0.4.21.
