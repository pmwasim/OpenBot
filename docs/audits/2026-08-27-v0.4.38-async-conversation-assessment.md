# OpenBot v0.4.38 async conversation assessment

Date: 2026-08-27
Scope: durable named-bot conversation consistency for asynchronous tasks

## Outcome

The release closes a timing window where a completed asynchronous named-bot task could become visible before its assistant message was persisted. User and assistant messages are now validated first and appended under one store lock, so readers observe the exchange together.

## Product assessment

- End-user value: completed named-bot tasks immediately show a complete conversation in the dashboard, API, and CLI.
- Old-laptop fit: the change uses the existing append-only JSONL store and stock Node.js; it adds no service, model, network, or paid dependency.
- Boundary: the batch operation preserves existing role, length, redaction, and bot-ownership validation. It changes durability timing only and does not grant tools or permissions.

## Verification

- Release harness: 156/156 checks passed, including the asynchronous named-bot regression, API/CLI parity, task queue, worker boundaries, audit redaction, and public-surface checks.
- The prior failing run reproduced the race before the fix; the corrected path passed the same full harness.
- Independent exact-commit standard security scanning is the release gate; the final scan covers the repository source and records the external-deployment limitation separately from source findings.

## Remaining gap

This fixes same-process durable ordering. Multi-user authorization, encrypted-at-rest storage, and external deployment hardening remain outside the supported single-user local boundary.
