# OpenBot v0.4.27 persistent-bot-conversation assessment

Date: 2026-08-27  
Implementation commit: `fdaa654`

## Outcome

OpenBot v0.4.27 makes durable named-bot conversations usable across clients. The daemon exposes bounded redacted message history at `GET /api/bots/:id/messages`. Selecting a named bot in the dashboard loads that history and refreshes it when a bot task reaches a final state. `openbot bot history <id>` reads the same contract locally or through the shared daemon.

## Product assessment

This closes the gap between a named bot profile and a usable persistent assistant. Operators can return to a bot and see its prior exchanges without opening raw task audits, while task execution still uses the existing durable task, approval, and workspace boundaries. The dashboard, local CLI, and daemon CLI now expose one conversation contract. The change adds no account, database, service, dependency, GPU requirement, or mandatory spend.

## Security and privacy assessment

The history endpoint exposes only an existing bot's message records, not bot instructions or full task events. The store caps history at 40 messages and each returned message at 12,000 characters; content is redacted again at delivery and only the allowlisted fields `id`, `role`, `content`, `taskId`, and `createdAt` are returned. Bot ids are URL-decoded and looked up by the durable store; unknown bots return 404. Existing no-cache JSON headers, loopback defaults, LAN bearer authentication, provider boundaries, approval gates, and workspace binding remain in force. Dashboard rendering uses text nodes rather than HTML injection.

## Remaining gaps

Conversation search, explicit conversation deletion/export, binary artifacts, archive downloads, retention controls, encrypted-at-rest storage, signed exports, desktop automation, connectors, signed extensions, collaboration, multi-user authentication, remote workers, and full-duplex clients remain future work. These are intentionally not represented as completed by v0.4.27.
