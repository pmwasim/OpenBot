# OpenBot v0.4.39 dashboard audit

Date: 2026-08-27

## Scope

Audited the local dashboard at `http://127.0.0.1:4178/` through the in-app browser at the default and 1024×700 laptop-sized viewports. The flow covered initial load, task form readiness, an invalid task submission, and the visible recovery state.

## Findings and disposition

1. Initial load was structurally healthy: the primary task form, local model status, named bots, memory, skills, connectors, approvals, routines, and task history were discoverable in the visible page and DOM.
2. Before this release, a failed task start was rendered as “OpenBot could not reach the local service,” which hid server validation failures. The browser reproduction showed the dashboard itself healthy while the task failure was actionable. v0.4.39 now preserves the returned server message.
3. Before this release, native inputs and selects rendered as bright default controls against the dark theme, reducing readability and visual consistency at laptop widths. v0.4.39 adds dark themed controls, visible focus rings, usable textarea sizing, and grouped pack controls.
4. Before this release, stable `/app.js` and `/styles.css` URLs were cacheable for one hour. A browser retained the previous dashboard after the fix, proving that a release could appear incomplete until cache expiry. v0.4.39 serves HTML, JavaScript, and CSS with `no-store`; the harness asserts this contract.
5. The narrow viewport keeps the main task flow reachable and hides the secondary rail, but the icon-only navigation remains visually terse. Its accessible names are present in the DOM; a future iteration should consider a compact tooltip or accessible mobile menu if navigation depth grows.

## Verification

- Release harness: `158/158 passed` after the dashboard fixes.
- Browser evidence: actionable server error text was visible after a fresh asset refresh; laptop-width controls were styled and focusable.
- Limits: this is a local visual/interaction audit, not a full screen-reader, keyboard-only, color-contrast, mobile-device, or external deployment certification. The local model was not required for this error-path audit.
