# OpenBot v0.4.22 settings assessment

Date: 2026-08-27  
Implementation commit: `993bd635c0d8743e4059297b6bee28d652e38502`

## Outcome

OpenBot v0.4.22 wires the dashboard Settings control to a read-only `/api/config` endpoint. The view reports effective daemon binding, local-only state, provider mode, model protocol and endpoint, resource profile, isolation mode, and agent limits. It reuses the existing redacted public configuration contract and directs operators to environment configuration plus daemon restart for changes.

- `npm run check`: passed, 113/113 release checks.
- The harness calls `/api/config` and verifies safe values, read-only behavior, and that no provider credential is returned.
- Existing checks continue to cover provider/model routing, remote opt-in, local-only defaults, approvals, workspace containment, cancellation, audit redaction, authentication, live activity, notification degradation, old-laptop limits, and public brand-neutrality.

## Product assessment

This closes an operator-facing setup gap: the dashboard now explains which effective configuration is actually in use without requiring terminal inspection. The feature adds no settings database, file mutation, service manager, account, dependency, GPU requirement, or mandatory spend. Configuration remains portable across older laptops because the view is a small local request and DOM-rendered response.

## Security and privacy assessment

The endpoint exposes the same non-secret configuration intended for local diagnostics. Provider keys are represented only as set/unset status, and endpoint userinfo is removed by the provider description path. The dashboard renders values through text nodes, not HTML interpolation. The endpoint inherits loopback defaults and LAN bearer authentication from the daemon and does not change task or worker permissions.

## Remaining gaps

Editable settings, secret-vault UX, provider-specific configuration, mobile/OS notifications, desktop automation, connectors, signed extensions, collaboration, multi-user authentication, remote workers, and full-duplex clients remain future work. These are intentionally not represented as completed by v0.4.22.
