# OpenBot v0.4.26 artifact-access assessment

Date: 2026-08-27  
Implementation commit: `e92229b`

## Outcome

OpenBot v0.4.26 adds typed task-artifact inventory and selective access. The daemon reports only files produced by successful `file.write` or `browser.fetch` actions at `GET /api/tasks/:id/artifacts`. A selected entry can be previewed at `GET /api/tasks/:id/artifacts/:path`. The dashboard links to the inventory, and `openbot artifacts <task-id>` works against either the local store or shared daemon.

## Product assessment

This improves the end-user bot workflow from “the task ran” to “the bot produced these files, and I can inspect the one I need.” It keeps the full audit bundle available for evidence while offering a small inventory and targeted preview for scripts, dashboard users, and older laptops. The capability adds no account, database, service, dependency, GPU requirement, or mandatory spend.

## Security and privacy assessment

Inventory entries are derived from successful action events only and capped at 50. Artifact access requires both the task id and an exact inventoried relative path, then uses the task’s canonical workspace with the existing no-follow file checks. Content previews are redacted and capped at 64 KiB; oversized files are rejected rather than loaded. Existing no-cache JSON headers, loopback defaults, LAN bearer authentication, approval gates, and task/workspace binding remain in force.

## Remaining gaps

Binary artifact handling, archive downloads, retention controls, encrypted-at-rest storage, signed exports, mobile/OS notifications, desktop automation, connectors, signed extensions, collaboration, multi-user authentication, remote workers, and full-duplex clients remain future work. These are intentionally not represented as completed by v0.4.26.
