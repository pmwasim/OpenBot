# OpenBot v0.4.18 live task stream assessment

Date: 2026-08-27
Implementation commit: `0c8863222dc6100029fff3fde0728bada955aae8`
Scope: durable task-event streaming, dashboard live activity, fallback behavior, and resource bounds.

## Outcome

OpenBot now exposes `/api/tasks/:id/events/stream?after=<offset>` as a bounded server-sent event stream. It replays durable events after the requested offset, subscribes to newly appended events, includes the current task projection, and closes after a final completed, failed, or cancelled state or a server time limit. The dashboard prefers this stream for active tasks and falls back to existing offset polling when the browser cannot use it or the connection fails.

Pause, resume, cancel, approval, audit, workspace, bot, skill, and redaction boundaries remain separate and authoritative. Paused and approval-waiting tasks keep their stream available for later operator changes; the stream does not authorize or execute work.

## Product and older-laptop assessment

This closes the dashboard’s live-activity requirement and makes task progress feel continuous without polling every active task on a fixed interval. One lightweight connection replaces repeated activity requests while the server limits the connection with heartbeats and a maximum lifetime; clients retain a polling fallback for compatibility.

The implementation remains suitable for the legacy CPU-only profile. It uses stock Node.js response streaming and the existing append-only store, bounded event payloads, task limits, worker limits, and local daemon process.

## Security assessment

The stream is served behind the daemon’s existing loopback default and optional bearer-authenticated non-loopback boundary. It exposes only the requested task’s existing redacted event records and task projection; task ids and offsets are validated, and subscriber callbacks cannot change durable writes. The independent final-tree security scan is recorded for this release.

## Remaining gaps

This is server-to-client live activity, not a full-duplex remote control channel. Native desktop packaging, push notifications, multi-user identity, connectors, signed extensions, and remote workers remain future work. OpenBot remains local-first and zero-cost by default.
