# OpenBot v0.4.15 in-flight cancellation assessment

Date: 2026-08-27  
Scope: race-safe task startup and in-flight model, shell, and browser cancellation  
Audited implementation commit: 73503ceb377d5fa425237d48577ca7de85a52246

## Product result

OpenBot now registers a per-task abort controller before claiming new or pending work. Pause and cancel transitions abort that controller, and the signal reaches local model requests, shell child processes, and browser fetches. New and pending tasks are claimed before the controller starts, preventing a concurrent stop from being overwritten by late startup state.

The agent still stops cooperatively at model and action boundaries. A completed file or worker effect cannot be undone by a later cancellation request; approval and workspace controls remain the prevention boundary for consequential effects.

## Evidence

- The fresh release harness passed 98/98 checks after the implementation commit.
- End-to-end daemon coverage starts a waiting model task, cancels it through the task-control API, and verifies the request terminates with cancelled state and no false completion event.
- Controller coverage verifies abort-signal propagation; shell coverage verifies child termination on an already-aborted signal.
- Existing approval, workspace containment, recovery, activity, audit redaction, old-laptop profile, and public-surface brand-neutrality checks remain green.
- `node --check lib/agent.mjs`, `node --check lib/provider.mjs`, `node --check lib/workers/shell.mjs`, `node --check lib/workers/browser.mjs`, `node --check lib/engine.mjs`, `node --check server.mjs`, and `git diff --check` passed.
- No runtime dependency, hosted service, account, telemetry, or paid integration was added.

## Older-laptop assessment

Cancellation uses stock `AbortController`, one in-memory controller per active task, and bounded process/network cleanup. It does not increase model context or agent turn/action limits and remains compatible with the existing no-container legacy profile.

## Security boundary

Only the daemon's validated pause/cancel task transitions can trigger active-task aborts. Model output cannot control the signal. The store remains authoritative for task state, approval consumption, workspace containment, and audit events; active task identifiers are isolated in memory and never persisted as credentials.

## Remaining gaps

- Hard rollback of already-completed effects, native desktop packaging, notifications, full-duplex streaming, multi-user identity, connectors, signed extensions, and remote workers remain incomplete.
