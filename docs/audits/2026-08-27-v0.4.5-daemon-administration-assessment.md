# OpenBot v0.4.5 daemon administration assessment

Date: 2026-08-27  
Scope: daemon-routed administration for local memory, skills, bots, and routines  
Audited implementation commit: 383ce64abee56c2c67ee0b8467eb915ef9aceeb5

## Product result

OpenBot's CLI can now manage server-owned local memory, reusable skills, named bots, and routines through the shared daemon with `--daemon`. Named-bot chat and routine Run now execute through the daemon's existing bounded agent loop, so the CLI can operate against the same durable state as the dashboard without maintaining a second populated local data directory.

Direct local administration remains available when the daemon is not running. The feature keeps the product local-first, zero-cost by default, and usable on older CPU-only laptops.

## Evidence

- The release harness passed 88/88 checks, including daemon-routed add, list, delete, chat, pause, enable, and Run now flows.
- The isolated client verification uses a separate empty data directory and confirms administration and task execution are owned by the live daemon.
- Named-bot chat and routine Run now return completed bounded results through the shared server path.
- Existing memory scoping, skill selection, bot workspace association, routine scheduling, approvals, task identity, event history, and audit recording checks remain green.
- No runtime dependency, hosted service, account, telemetry, or paid integration was added.

## Older-laptop assessment

Administration uses one bounded HTTP request per operation. Named-bot chat and routine Run reuse the existing daemon controller and model request path; they do not start a second controller or model process. The legacy resource profile and direct local path remain available for low-resource or offline operation.

## Security boundary

Daemon routes reuse the existing request bounds, bearer-token behavior for explicitly protected non-loopback use, workspace validation, policy engine, approval gates, redaction, and audit events. Resource identifiers are URL-encoded by the client. Skills remain declarative untrusted guidance and cannot grant tools or bypass policy.

## Remaining gaps

- Desktop packaging, OS service installation, full-duplex streaming, notifications, multi-user identity, connectors, signed extensions, and remote workers remain incomplete.
- The scheduler runs while the local daemon is running; laptop sleep or shutdown stops host-local work.
