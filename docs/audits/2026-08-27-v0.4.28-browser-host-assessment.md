# OpenBot v0.4.28 browser-host assessment

Date: 2026-08-27  
Implementation commit: `936358f`

## Outcome

OpenBot v0.4.28 makes ordinary browser research possible without weakening local-first defaults. Browser URLs remain restricted to `127.0.0.1` and `localhost` unless the operator sets `OPENBOT_BROWSER_ALLOW_HOSTS` to a comma-separated exact host list. The configured list is visible in read-only Settings, is enforced by policy and the worker, and browser fetches still require approval before content is saved into the task workspace. Redirects are disabled.

## Verification

- `git diff --check`: passed.
- Node syntax checks for configuration, policy, browser worker, engine, daemon, CLI, and dashboard: passed.
- `npm run check`: passed, 137/137 release checks.
- Exact-host policy checks confirmed default loopback denial, explicit host approval eligibility, and subdomain denial.
- Daemon configuration check confirmed the allowlist is parsed, deduplicated, exposed safely, and does not include malformed URL entries.
- Engine integration confirmed a configured external host returns `needs_approval` without making a network request.

## Product assessment

This closes a major everyday-bot gap: an operator can authorize a bounded set of documentation or research hosts while retaining the same browser-fetch tool and task artifact flow. It adds no browser automation dependency, account, database, GPU requirement, hosted service, or mandatory spend, and remains usable on older CPU-only laptops.

## Security and privacy assessment

The default remains loopback-only. Host matching is exact and case-normalized; URL credentials are rejected by the existing policy, redirects are disabled at the worker, and configured hosts only make a request approval-eligible. Approval, workspace containment, file no-follow checks, cancellation, audit redaction, loopback/LAN authentication, and public brand-neutrality remain in force. Invalid host entries fall back to the safe loopback defaults rather than broadening access.

## Remaining gaps

Browser authentication profiles, cookie vaults, JavaScript-rendered pages, download controls, DNS-rebinding defenses, isolated browser profiles, MCP/connectors, desktop automation, signed extensions, collaboration, multi-user authentication, remote workers, and full-duplex clients remain future work. These are intentionally not represented as completed by v0.4.28.
