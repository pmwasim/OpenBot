# OpenBot v0.4.7 service integration assessment

Date: 2026-08-27  
Scope: opt-in per-user daemon service integration  
Audited implementation commit: 1dfa9d4de32b95803c4dee87a81c555defec488e

## Product result

OpenBot can now generate, inspect, install, enable, disable, and remove a per-user service definition for the existing local daemon. macOS uses a LaunchAgent; Linux uses a systemd user service. `service install --dry-run` and `service uninstall --dry-run` preview the exact result without writing files or invoking a service manager.

The service path is opt-in and reversible. The existing foreground, detached, and desktop launcher paths remain available, so OpenBot does not require an operating-system service manager or elevated privileges for normal use.

## Evidence

- The release harness passed 92/92 checks, including macOS and Linux manifest generation and explicit unsupported-platform behavior.
- Service definitions use the existing daemon entry point, configured data directory, PID record, host, and port; they do not create a second agent controller.
- Service files are written only under the current user's service directory with restrictive file permissions.
- Existing daemon lifecycle, loopback, authentication, workspace, approval, redaction, audit, recovery, administration, worker, dashboard, and public-surface checks remain green.

## Older-laptop assessment

The service integration uses stock Node.js and the operating system's existing user service manager. It adds no container, native runtime, hosted service, account, telemetry, or paid dependency. Unsupported platforms retain the portable detached and desktop launcher fallback.

## Security boundary

`service install` applies the same bind-host validation as daemon startup. The generated service invokes the repository's existing foreground server and carries only the configured local runtime values. Installation is explicit; dry-run mode performs no filesystem or service-manager mutation. Service files are not treated as authorization credentials.

## Remaining gaps

- Native desktop packaging, notifications, full-duplex streaming, multi-user identity, connectors, signed extensions, and remote workers remain incomplete.
- Service installation is currently implemented for macOS and Linux user services; other platforms use the portable launcher path.
