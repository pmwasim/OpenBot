# OpenBot v0.4.36 queue recovery assessment

Release: v0.4.36  
Assessment date: 2026-08-27  
Scope: durable queue admission and daemon restart behavior.

## Product outcome

OpenBot now records when an asynchronous task enters, is admitted from, and leaves the daemon queue. Pending tasks that were waiting in the queue when the daemon stopped can be recovered automatically after restart, subject to the same resource-aware capacity limits.

## Safety and reliability assessment

- Only pending tasks whose latest queue event is `task.queued` are automatically recovered.
- Tasks that reached `task.admitted` are not replayed automatically; operators must explicitly resume them.
- Queue state is part of the durable task projection and survives store reopen.
- Queue recovery uses the existing task, workspace, provider, policy, approval, and audit boundaries.
- No unbounded in-memory backlog, dependency, account, remote worker, or mandatory spend is introduced.

## Verification evidence

- Red phase: the release harness failed because queued task state was not durable.
- Green phase: durable queue-state projection, recoverable-queued-task selection, existing queue behavior, all client/API flows, and the full release harness pass after implementation.

## Known limits

The in-memory queue is reconstructed from durable queued events and is not a distributed scheduler. Tasks already admitted before a crash are intentionally not replayed automatically; this avoids duplicate effects but requires explicit operator resume.
