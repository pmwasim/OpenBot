# OpenBot v0.3.8 recovery assessment

Date: 2026-08-27

## Scope

This assessment covers the restart-safe task recovery increment at commit `dd6e0bdd1bc783ea975d9966a9df43372c129030` plus the dashboard, CLI, documentation, and verification changes for v0.3.8. OpenBot remains a local-first, zero-cost project: no hosted service, account, paid dependency, or mandatory network call was added.

## Product result

OpenBot now keeps an interrupted task recoverable when its durable record is left in `running` state. An operator can resume that task through:

- `POST /api/tasks/<task-id>/resume`
- `node cli/openbot.mjs resume <task-id> --json`
- the Resume control in the recent-task dashboard cards

Recovery reuses the original task ID, workspace, bot association, skill, and event history. Bot-owned tasks recover their bot context, and approval-bound work continues to use the existing one-shot approval and action-digest checks.

## Older-laptop assessment

The recovery path does not add a runtime dependency, container requirement, GPU requirement, hosted worker, or background service. The legacy resource profile remains bounded to three turns/actions with compact context and allowlisted diagnostics that can run without container isolation. A local model is still required for natural-language reasoning; the project does not claim that every old laptop can run every model.

## Verification evidence

- `npm run check`: 80/80 release-harness checks passed.
- `git diff --check`: passed.
- JavaScript syntax checks for server, CLI, store, agent, provider, configuration, dashboard, and harness: passed.
- Public surface scan for outside product branding: clean.
- Security review: run against the exact release commit; reportable findings and deferred in-scope surfaces are recorded in the sealed scan result.

## Remaining gaps

The local scheduler still runs only while the daemon is running. Multi-user identity, encrypted-at-rest storage, external connectors, desktop automation, signed extensions, richer provider adapters, and a complete packaged installer remain future work. These are not silently represented as shipped capabilities.
