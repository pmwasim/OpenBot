# OpenBot v0.4.19 model-selection assessment

Date: 2026-08-27  
Implementation commit: `700210584c5a0939e3663439dc17f23fd8328ee3`

## Outcome

OpenBot v0.4.19 adds an explicit per-task local model choice to the dashboard. The selector is populated from the daemon health response, keeps a valid operator choice across refreshes, and defaults to the first available local model when left automatic. New tasks, resumed tasks, and approval continuations send the selected model to the existing server routes.

The server remains authoritative: model availability is resolved and validated by the daemon, and local-only provider policy is unchanged. This release does not claim a complete provider-settings UI; provider configuration and optional external adapters remain operator-configured and incomplete roadmap work.

## Product assessment

The change closes a concrete usability gap: operators can now choose among installed local models without editing code or relying on an implicit first-model choice. The same choice is available when recovering work or continuing after an approval decision. The interface remains lightweight and does not add a dependency, hosted account, GPU requirement, or mandatory spend.

The release remains portable for older CPU-only laptops. Model execution still depends on an installed compatible local runtime, and the existing legacy resource profile continues to cap turns/actions and allow only bounded diagnostics where isolation is unavailable.

## Security and privacy assessment

The selector accepts display data from the daemon through DOM text nodes; it does not use HTML interpolation. User-selected values are sent to existing authenticated/loopback task routes and pass through existing server model validation. No credentials are added to the browser, prompts, logs, or public UI. The public-surface brand-neutrality check remains enabled.

## Remaining gaps

Provider settings, credential storage UX, richer provider adapters, desktop-native packaging, connectors, signed extensions, collaboration, multi-user authentication, remote workers, and full-duplex clients remain future work. These are intentionally not represented as completed by v0.4.19.
