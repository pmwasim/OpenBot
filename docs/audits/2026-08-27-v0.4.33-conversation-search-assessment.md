# OpenBot v0.4.33 conversation search assessment

Release: v0.4.33  
Assessment date: 2026-08-27  
Scope: bounded search across persistent named-bot conversation history.

## Product outcome

The feature closes a practical usability gap in persistent local bots. Operators can search the selected bot's recent conversation in the dashboard, query the API with `q`, or use `openbot bot history <id> --query <text>`. Empty search preserves the existing history view.

Search is intentionally narrow: it filters only the selected bot's existing capped message history. It does not become a general task, workspace, or cross-bot search index.

## Safety and portability

- Search terms are capped at 120 characters and overlong queries return a clear client error.
- Results retain the existing 40-message bot-history cap and redacted message fields.
- The server/store remains authoritative; the dashboard and CLI are thin clients.
- No new dependency, account, background service, model, network call, or mandatory spend is introduced.
- Public surfaces remain brand-neutral.

## Verification evidence

- `npm run check` — PASS, including store filtering, API query behavior, overlong-query rejection, CLI wiring, and dashboard search controls.
- The existing bot persistence, bounded-history, approval, workspace, authentication, redaction, and public-surface checks remain covered.

## Known limits

Search covers only the most recent bounded messages retained by the local bot profile. Full-text indexing, cross-bot search, task-event search, deletion/retention controls, and remote clients remain separate roadmap work.

## Release gate

Release is eligible after the standard repository security scan reports complete coverage and zero reportable findings on the final commit, followed by terminal verification of the pushed commit, tag, release state, and clean worktree.
